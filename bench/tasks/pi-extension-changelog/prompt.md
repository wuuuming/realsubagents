Pi shows its own changelog after an update, but extension packages get nothing: after `pi update --extensions` the user cannot see what changed in their extensions (issue #5958). Show extension changelogs the way Pi shows its own.

Behaviour (packages/coding-agent):
- A package can name its changelog with `pi.changelogPath` in its `package.json` (resolved relative to the package root); otherwise a `CHANGELOG.md` at the package root is used. A `changelogPath` that resolves outside the package root is ignored (and the `CHANGELOG.md` fallback is then not used either). A manifest that declares only `changelogPath` must not stop resources from being auto-discovered. The resolved absolute path is carried through package resource metadata (`metadata.changelogPath`) and `SourceInfo.changelogPath`.
- Pi stores, in global settings, the last seen version of each extension package. On a fresh interactive launch (not a resumed session: one whose messages are non-empty is skipped, and nothing is recorded), it compares the stored version with the installed package version (from the package's `package.json`). The first time a package is seen, its version is recorded without showing anything. When the version has changed, the changelog entries newer than the stored version and up to the installed version (`[Unreleased]` is never shown) are shown in an "Extension Updates" section, and the installed version is recorded. Only extensions that come from packages (`origin: "package"`) with a changelog count, and several extensions from the same package produce one section. The `collapseChangelog` setting condenses this to one line per package.

Interface the tests use:
- `src/core/source-info.ts`: `SourceInfo.changelogPath?: string`, and `getSourcePackageKey({ source, scope }): string`, the key under which a package's last seen version is stored.
- `SettingsManager.getExtensionChangelogVersion(key)` / `setExtensionChangelogVersion(key, version)`, stored in global settings.
- On `InteractiveMode`: `getExtensionChangelogUpdates(): { name: string; version: string; markdown: string }[]`, using only `this.session.state.messages`, `this.session.resourceLoader.getExtensions()`, `this.settingsManager` and `this.readPackageJson(packageRoot)` (a new method returning the parsed `{ name?, version? }` or `undefined`). It records versions as a side effect. `markdown` is the selected entries with each heading prefixed by the package name, e.g. `"## pi-demo-extension [1.2.0]\n\n- Added feature B\n\n## pi-demo-extension [1.1.0]\n\n- Added feature A"`.

Document it in `docs/packages.md` and `docs/settings.md`, and update `schemas/settings.schema.json`. Add tests, and keep the rest of the coding-agent test suite passing.
