Three unrelated problems in three packages. Fix all three; each fix is independent of the others.

1. **packages/tui: Shift+Enter in Apple Terminal.** Some Apple Terminal setups send `ESC` + `CR` (`"\x1b\r"`) for Shift+Enter. Pi parses it as Alt+Enter and queues a follow-up message instead of inserting a new line (issue #11559). The native Shift fallback in `src/terminal.ts` (`normalizeNativeShiftEnterInput(data, nativeShiftSupported, shiftPressed)`) already rewrites a plain `CR` to the CSI-u Shift+Enter sequence `"\x1b[13;2u"` when Shift is held; it must do the same for `ESC` + `CR`. Without Shift held, or without native Shift support, `"\x1b\r"` stays as it is. Update `docs/terminal-setup.md` in packages/coding-agent if it describes this fallback.

2. **packages/chord: escape-sequence fragments in tool output.** `sanitizeOutput()` (`src/output.ts`) removes the ESC byte with the other control characters but leaves the rest of each escape sequence, so colored output `"\x1b[31mERROR\x1b[0m"` comes back from `OutputBuffer.snapshot()` as `"[31mERROR[0m"`, which later ANSI stripping can no longer recognize. Remove whole 7-bit escape sequences: CSI sequences (colors, cursor, erase), string sequences (OSC, DCS, APC, PM, SOS) terminated by BEL or `ESC \`, and short `ESC x` forms such as `ESC ( B` or `ESC 7`. A sequence split across chunks pushed to an `OutputBuffer` must also be removed from its snapshot. Examples: `"\x1b[1;38;5;208mx\x1b[?25l\x1b[2K\x1b(By\x1b7z"` → `"xyz"`; `"\x1b]8;;https://pi.dev\x07link\x1b]8;;\x1b\\ \x1b]0;title\x07ok"` → `"link ok"`.

3. **packages/coding-agent: misleading `pi update` message under PNPM_HOME.** `detectInstallMethod()` (`src/config.ts`) classifies every path containing `/pnpm/` as pnpm. For an install that only lives under `PNPM_HOME`, such as a wrapper under `$PNPM_HOME/global-nub/5/node_modules/...` that is not managed by `pnpm root -g`, `pi update` correctly refuses to self-update but `getSelfUpdateUnavailableInstruction()` says "This installation is not managed by a global pnpm install. ..." (issue #7756). Name the package manager only when it actually owns the install (managed but not writable). In every other case print the neutral message: `Update <packageName> using the package manager, wrapper, or source checkout that provides this installation.`

Add tests for each, and keep the test suites of the three packages passing.
