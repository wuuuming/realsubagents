Two unrelated problems in two packages. Fix both; the fixes are independent of each other.

1. **packages/coding-agent: Windows helpers fail from deep directories under WSL, and external editor failures are silent.** WSL starts Windows programs in the current directory, translated to `\\wsl.localhost\<distro>\<cwd>`; when that path exceeds MAX_PATH, every Windows program fails to start. Pi spawns its clipboard helpers (`runClipboardCommand` in `src/utils/clipboard-command.ts`, e.g. `powershell.exe`) and the browser opener (`openBrowser` in `src/utils/open-browser.ts`) in its own cwd, so in a deep project directory image paste returns nothing, copying fails and sign-in cannot open the browser (issue #11592). These helpers never use the cwd, so run them from the filesystem root on POSIX. The external editor keeps Pi's cwd on purpose (project-relative paths); add a comment saying why.
   Separately, external editor failures are invisible because the UI redraws over the error. `editInExternalEditor` must return `{ status: "failed", message }` with `Failed to launch external editor: <command>` when the editor cannot be started, `External editor exited with code <n>; prompt unchanged` on a non-zero exit, or a message naming the signal. Show the message in the status line for the main editor and inline in the extension editor dialog.

2. **packages/durable: tool search ranks poorly.** pi-durable keeps its own copy of the tool ranker (`rankDocuments()` in `src/search.ts`), which predates the coding agent's ranking fixes (`Bm25Ranker` in `packages/coding-agent/src/extensions/tool-search/tool.ts`). Searching `thread_read` with limit 1 returns `queue_read`, and a tool whose name is in the query (`peekaboo app`) loses to tools that only mention the words in their descriptions. Bring durable's ranking in line with the coding agent's:
   - a tool's name is its own field (`SearchDocument.name`; the search text no longer repeats the name), weighted above any number of description mentions;
   - a query that is exactly a tool's name ranks it first, and a tool whose whole local name (after the `mcp__<server>__` prefix) appears in the query gets a bonus worth one more match of every query term;
   - namespace text is an optional separate field, `SearchDocument.namespaceText`, weighted 0.5 and not length-normalized; `searchTools()` includes the namespace instructions in it, as the coding agent does;
   - coverage first: a tool matching more of the query's distinct terms (in any field) ranks above one matching fewer, whatever the scores. For example `screenshot window` must rank an `image` tool described as taking screenshots of windows above a `window` tool.
   Update `docs/spec.md` where it describes the ranking.

Add tests for each, and keep the test suites of the two packages passing.
