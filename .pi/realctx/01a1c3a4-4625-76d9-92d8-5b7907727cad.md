`node bench/run.ts <task> --arm rsa|rsav1` runs `bench/dryrun.ts`. Arm `rsa` uses `prompts/v0`, `rsav1` uses `prompts/v1` (D-26).
- **Agents:** orchestrator + workers w1/w2, each `pi --mode rpc` with `-e extensions/rsa-relay-tools/index.ts` (`RSA_ROLE=orchestrator|worker`; tools rsa_dispatch/rsa_steer/rsa_finish or rsa_report) and `--append-system-prompt <prompts>/<role>.md` (+ `overlays/<provider>-<role>.md`). The orchestrator runs with `--exclude-tools edit,write` in the main tree; workers get their own seeded worktrees.
- **Relay loop:** reads tool calls from `tool_execution_start`. On a worker report: commit (`git add -A`, then `git reset` of the harness paths), deliver the Report to the orchestrator; when all are done, merge into the orchestrator's tree. At the end, `git reset <base>`, so acceptance sees a working-tree diff. A text-only stop gets at most 2 continuations; every message ends with `elapsed Ns`.
- **Pitfalls:**
  - dryrun.ts must not value-import run.ts (top-level-await cycle: the process silently exits). Helpers are passed in as a parameter.
  - A dead Pi child causes stdin EPIPE; src/rpc.ts has an error listener and `onExit`.
  - Kill leftovers per agent tree: every Pi command line contains the runDir.
  - Pi ignores `streamingBehavior` when idle, so always pass it.
  - `git add` exclude pathspecs fail on gitignored paths.
- **Analysis:** `node bench/compare.ts [--arm rsa|rsav1] [--json out]` gives per-task ratios against the baseline, the G0.05 verdict, H-3 serial fraction, H-5 orchestrator share and worker session shape.
