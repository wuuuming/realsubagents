**Design (2026-11 reset): smallest possible subagent system.** A subagent system only delegates:
- no steering
- no reuse
- no nesting/derived agents
- no scale/escalation policy. Whether to delegate, how to split, and how many subagents to run is the user's or main agent's decision, because tasks differ in type and scale. Don't add heuristics, thresholds or splitting rules to the tool or its prompt.

**User's choices:**
- Subagents run in the same working tree (no worktrees, merge or checks).
- One blocking call returns the final message.
- Children can't delegate.
- Old code tagged, then deleted.

**Layout and current code:**
- `extensions/realsubagents/index.ts` registers one tool, `subagent` with param `{task}`. It is skipped when `RSA_SUBAGENT` is set.
- `src/subagent.ts` `runSubagent()` spawns `node <pi cli.js> --mode json --no-session --append-system-prompt <SUBAGENT_PROMPT> [--model provider/id] [--thinking lvl]`.
  - The task goes in on stdin, which Pi prepends as the first prompt. This avoids `@file` expansion and argv limits.
  - The result is the text of the last assistant `message_end`. Usage is summed and returned as the tool result's `usage`, so it counts in the parent's totals.
  - Abort uses `taskkill /T /F` on Windows, or a process-group kill elsewhere.
- `src/pi-cli.ts`.
- `tests/subagent.test.ts` with the fake CLI `tests/fixtures/fake-pi.mjs`.
- `scripts/smoke.ts`.
- Parallelism comes only from Pi running several tool calls of one message in parallel.
- There are no docs/route/bench any more. Do not reintroduce planning docs (gates, route IDs, status logs) unless asked.

**Removed (kept at git tag `split-runtime-v0.1`):** coordinator (rsa_split/steer/finish), SQLite store/resume, worktrees/merge/checks, bench/ (runner, tasks, pins, ledger), prompts/, reports/, docs/ (design + route), experiments/.

**Historical results at that tag:** baseline 32/32 at $50.19. The v0.05 dry run with prompts v1 found 2 parallel workers took 63% of the time and 89% of the cost of a single session. $109 of the $215 benchmark cap had been spent.

**Dev commands:**
- `npm run typecheck`: tsc 7 with `erasableSyntaxOnly`, so no parameter properties and no enums.
- `npm test`: runs `node --test tests/*.test.ts`. TS runs via Node type stripping; there is no build step. Uses the fake Pi via a `pi` option/`RSA_PI_CLI`, so no model calls.
- `npm run smoke`: live run.
  - A real Pi in `--mode json --no-extensions -e <ext>` calls subagent, whose child writes smoke.txt.
  - Costs about $0.10 on the default model; `--model` overrides.
  - Passed on Pi 1.5.1.

**Spawning child Pi on Windows:**
- `pi` is a launcher that spawns a second node, so spawn child Pi directly as `node <cli.js>`.
- `findPiCli()` lookup order: `RSA_PI_CLI` → `RSA_PI_VERSION` → `~/.pi/agent/install/current-version` → local package.
- Add `PI_MANAGED_INSTALL_ROOT` via `piChildEnv`.
- JSON/RPC framing must split on LF only. Do not use readline.
