**Tasks & repos**
- v0.0 task set: `bench/tasks/`, 13 tasks (route D-21/D-22). All 13 validated on 2026-11-09 (commit affbdd6).
- `bench/tasks/<id>/task.json`: repo, base commit, source commit, label, withhold[] (test paths checked out from `source` only at acceptance), acceptance.command, optional regression {command, parser cargo|vitest-json|node-tap, baselineFailures}. Plus `prompt.md`.
- Large-parallel tasks are composites: `parts: [{source, withhold}]` plus explicit `k` (validateTask requires `k >= 2` for large-parallel). They have one regression entry per package, each with its own `baselineFailures` file (e.g. baseline-failures-tui.txt).
- Composite base: pick a common base that is an ancestor of every part's parent, then check that every part's diff applies: `git diff --binary P^ P -- . ':(exclude)**/CHANGELOG.md' | git apply --3way`. run.ts excludes `**/CHANGELOG.md` from reference diffs because changelog hunks make parts conflict.
- `bench/repos.json`: base clone, tree setup links/copies, seed mode, prepare commands.

**Validate a task for free**
- `bash bench/validate.sh <task>...` checks reference accepted and base rejected, and writes the baselines. It removes the old reference-1/base-1 run dirs itself. Default runs root: `$RSA_RUNS` or D:/rsa-bench/runs.
- `--mode base` must give accepted=false.
- `--mode reference --write-baseline` applies base..source (minus withheld), must give accepted=true, and writes the regression baseline list (failures the historical fix also has; e.g. pi tui has 5 Windows-only failures in autocomplete/terminal-image).
- Acceptance = named tests pass + no failures outside a baseline list (route D-18). Acceptance must name the task's own test files. Whole-suite commands fail on Windows due to pre-existing failures, so they go in `regression`.
- Test files with Windows-only failures (fail both before and after the change): a task whose acceptance runs the whole file never passes at the reference. Fix (used for 5 tasks): the acceptance command names only the commit's new tests (vitest `-t "name|name"`, node `--test-name-pattern=`). The regression check still runs the full files with baseline-failure lists.

**Runs**
- Output: `D:/rsa-bench/runs/<task>/<arm|mode>-<n>/` (result.json, meter.json, trace.jsonl, diff.patch, acceptance.log, regression.log). The run dir must not exist yet. The worktree is removed unless --keep; junction links are removed before deletion.
- Agent mode: pi RPC with `--no-extensions -e realctx -e realtasks -e extensions/rsa-bench-usage`, REALCTX_HOME=<run>/realctx, `--session-dir <run>/sessions`. realtasks is NOT isolated (state lives under PI_CODING_AGENT_DIR). Dialog requests get `cancelled: true`.
- Shell commands run through Git Bash (`C:/Program Files/Git/bin/bash.exe`, override RSA_BASH). Timeouts kill the process tree with `taskkill /T /F`.
- `--rescore <runDir>` rebuilds the tree at base, applies the run's saved `diff.patch`, and re-runs acceptance + regression with the current harness. It is free: cost and time stay as measured, and the old verdict goes to `result.json` `rescored.previous`. Use it after a harness fix instead of paying for a new agent run. Don't run it while a batch is running: CPU contention distorts the batch's wall-clock metric.
- D-18 flake rule: a regression check that shows new failures is run once more (logs `regression*-retry.log`). Only failures seen both times count; the rest go to `regression.flaky`. Example flake: `packages/chord/test/manager.test.ts` "child-owned kernel lock…" (spawns real child processes).
- Pitfall (fixed): acceptance first does `git add -A -N` to snapshot the agent's diff. Suppose the agent created a withheld test file that is new in source (absent at base). Deleting it from disk alone leaves an intent-to-add index entry, and `git apply --3way` then fails with "does not match index". The runner now runs `git rm -r -q --cached --ignore-unmatch` first.
- `bench/batch.sh [rounds]` runs G0.0 rounds (small N=3, large N=2, caps $5/$8). It skips existing baseline-N dirs and stops on the budget guard. Log: D:/rsa-bench/batch-g00.log.
